# Кейс 1: сигнальный советник MT5 → мессенджер MAX

**Стек:** MQL5, MAX Bot API, WebRequest, TLS (сертификаты Минцифры)

## Что сделано

Советник для MetaTrader 5, который анализирует золото (XAUUSD) — тренд на H4/D1, фильтр
объёмов, контртренд по уровням S/R и дивергенции RSI — и отправляет сигналы (вход,
стоп-лосс, тейк-профит) в приватный канал мессенджера MAX. Сам не торгует: только сигналы.

## Чем сложно

- **MAX, а не Telegram** — API Telegram из РФ заблокирован, поэтому интеграция с MAX Bot API
  (российский мессенджер для бизнеса).
- **TLS** — сертификат `*.max.ru` выпущен Минцифры, и Windows ему по умолчанию не доверяет.
  Пришлось установить корневой и промежуточный сертификаты в хранилище, иначе WebRequest
  советника не достучится до API.
- **Кириллица в JSON** — русский текст сигналов при отправке уезжал не в UTF-8; решено
  отправкой тела из UTF-8 файла (`--data-binary @file`).
- **chat_id канала** — событие «бот добавлен» приходит один раз; скрипт получения chat_id
  ждёт его через long-poll, а не читает «список чатов» (такого метода в MAX API нет).
- **Два канала** — VIP (сигнал мгновенно) и бесплатный (дайджест) — различаются только
  параметром chat_id, всё остальное одно и то же.

## Результат

Бот опубликован, сигналы доходят в оба приватных канала. Собрана продажная коробка:
`.ex5` + `.mq5` + инструкция по настройке + скрипт получения chat_id. Советник компилируется
0 ошибок / 0 предупреждений. Секреты (токен) в коробку не кладутся — покупатель вставляет свой.
